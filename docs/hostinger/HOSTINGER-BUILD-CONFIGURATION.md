# Hostinger Node.js Application Build Configuration

This document specifies the copy-ready configuration values to enter into Hostinger's Node.js Application Setup interface (hPanel / CloudPanel / cPanel Node.js Selector).

---

## 1. Hostinger Control Panel Field Mapping

| Hostinger Setting / Field | Exact Value to Enter | Explanation |
| :--- | :--- | :--- |
| **Application Root** | `.` (or `/home/username/public_html` / repository root) | The root directory containing root `package.json` and workspaces. |
| **Application Startup File** | `apps/api/dist/main.js` | Compiled entry point generated by NestJS CLI. |
| **Node.js Version** | `20.x` (or `18.x`) | LTS version compatible with `@nestjs/core@10.4.7` and `mongoose@8.8.1`. |
| **Application Mode / Environment**| `production` | Sets `NODE_ENV=production`. |
| **Package Manager** | `npm` | Native workspace support. |
| **Install Command** | `npm ci` | Installs exact dependencies from committed `package-lock.json`. |
| **Build Command** | `npm run build --workspace=packages/shared && npm run build --workspace=apps/api` | Compiles `@washora/shared` first, then builds the NestJS API. |
| **Build Output Directory** | `apps/api/dist` | Directory where compiled `.js` files reside. |
| **Application Port** | Leave default / Inherited from `process.env.PORT` | Hostinger injects `process.env.PORT` dynamically. |

---

## 2. Alternative Configuration (If Hostinger Application Root is set to `apps/api`)

If the hosting plan requires setting **Application Root** directly to `apps/api`:

1. Pre-build from repository root prior to deployment:
   ```bash
   npm ci
   npm run build --workspace=packages/shared
   npm run build --workspace=apps/api
   ```
2. In Hostinger:
   - **Application Root**: `apps/api`
   - **Application Startup File**: `dist/main.js`
   - **Node.js Version**: `20.x`
   - **Application Mode**: `production`

---

## 3. Verified Build Command Sequence

To test the build locally before deployment:

```bash
# Execute from Repository Root
npm ci
npm run build --workspace=packages/shared
npm run build --workspace=apps/api

# Verify build artifact exists:
# Windows: dir apps\api\dist\main.js
# Linux: ls -l apps/api/dist/main.js
```

Expected output: `apps/api/dist/main.js` is generated along with all module controllers, services, and schemas.
